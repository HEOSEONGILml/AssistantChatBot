# 배경 모드 스파이크 결과

- 날짜: 2026-10-14
- 환경: Windows 10 Pro 19045.6466, Tauri 2.12.3, `windows` 크레이트 0.62.2, 디스플레이 배율 100%(dpr=1), 1920×1080 단일 모니터
- 코드: `spike/background-mode` 브랜치 `spikes/background-mode/` (버림. 머지하지 않음)
- 계획: [2026-10-14-spike-background-mode.md](../superpowers/plans/2026-10-14-spike-background-mode.md)
- 확인 방법: 사용자가 PC를 비워 둔 동안 스크립트로 클릭·창 최소화를 하고 스크린샷과 앱 로그로 판정했다.

## 요약

| 질문 | 결과 | 한 줄 설명 |
|---|---|---|
| 1. 아이콘 뒤 레이어에 붙이기 | **조건부** | 붙이기는 된다. 하지만 투명이 안 돼서 배경이 검게 칠해진다. **앱이 배경화면 그림을 직접 그리면** 정상으로 보인다 |
| 2. 배경 모드 클릭 감지 | 된다 | 마우스 훅으로 강아지 클릭과 빈 바탕화면 클릭을 구분한다. 아이콘 동작을 방해하지 않는다 |
| 3. 말풍선 가림 판정 | 된다 | 다른 창과 작업 표시줄에 가려졌는지 맞게 판정한다 |
| 4. 바탕화면 노출·마지막 입력 | 된다 | 모든 창 최소화를 감지하고, 마지막 입력 후 경과 시간을 얻는다 |
| (대조) 오버레이 클릭 통과 | 된다 | 강아지 밖 클릭은 아래 창으로 통과하고, 강아지 클릭은 앱이 받는다 |

**가장 중요한 발견**: 이 스파이크에서 시도한 방법(웹뷰 투명 + 색상 키 2가지)으로는 배경 모드 창을 투명하게 둘 수 없었다. `UpdateLayeredWindow`, DirectComposition 직접 제어 등은 시도하지 않았다. 배경 모드는 "투명 창을 배경 위에 얹는 것"이 아니라 **"앱이 배경화면 자체가 되는 것"**으로 바꿔야 한다. 이는 스펙 3.2절의 설계를 바꾸는 결정이라 사용자 확인이 필요하다 (아래 "본 구현에 주는 결론").

## 질문별 상세

### 1. 아이콘 뒤 레이어에 붙이기

- 사용한 API: `FindWindowW("Progman")`, `SendMessageTimeoutW(0x052C)`, `EnumWindows` + `FindWindowExW("SHELLDLL_DefView")`, `SetParent`
- 확인 결과
  - ✅ 붙이기 성공. 강아지가 아이콘 **뒤**에 그려지고, 다른 창 뒤에 가려진다. 위치는 붙이기 전과 같다. 애니메이션도 계속 돈다.
  - ❌ **투명 영역이 검게 칠해져 배경화면이 가려진다.** 자식 창이 되면 웹뷰의 알파 투명이 합성되지 않는다.
    - 시도 1: 붙인 뒤 색상 키(`WS_EX_LAYERED` + `SetLayeredWindowAttributes(LWA_COLORKEY)`) → 자식 창에서 설정 자체가 실패했다.
    - 시도 2: 붙이기 전(최상위 창일 때) 색상 키 설정 → 여전히 검고, 창에 제목 표시줄 테두리까지 생겼다.
  - ✅ **대안 성공**: 현재 배경화면 파일(`SystemParametersInfoW(SPI_GETDESKWALLPAPER)`)을 읽어 웹뷰 배경으로 꽉 차게 그리고, 투명 없이 그대로 붙인다. 배경화면이 정상으로 보이고 강아지는 아이콘 뒤에서 움직인다. 배경화면 앱(Wallpaper Engine 등)과 같은 방식이다.
  - ⚠️ 탐색기(`explorer.exe`)를 재시작하면 강아지 창이 사라진다. 앱 프로세스는 살아 있다.
  - ⚠️ **붙은 상태에서 앱이 강제 종료되면 실제 바탕화면이 검게 남는다.** 탐색기 재시작으로 복구했다.
- 주의점
  - 앱이 그린 배경화면이 실제보다 색이 뭉개져 보였다(포스터화). 원인(배경화면 파일 화질 또는 렌더링)은 조사하지 않았다.
  - Rust 2024 에디션이라 `unsafe extern "system" fn` 안에서도 `unsafe { }` 블록이 필요했다. `windows` 0.62는 `FindWindowExW`·`SetParent`에 `Option<HWND>`를 받는다.

### 2. 배경 모드 클릭 감지

- 사용한 API: `SetWindowsHookExW(WH_MOUSE_LL)` (전용 스레드 + `GetMessageW` 루프), `GetForegroundWindow` + `GetClassNameW`
- 확인 결과 (배율 100%)
  - ✅ 강아지 클릭 `onDog=true`, 빈 바탕화면 클릭 `onDog=false`.
  - ✅ 훅을 건 상태에서 아이콘 더블클릭으로 폴더가 정상으로 열렸다. 훅은 클릭을 가로채지 않는다(`CallNextHookEx`).
  - ⚠️ 강아지 클릭 때 `fg=Tauri Window`가 찍혔다. 하지만 훅 시점의 전경 창은 클릭 **직전** 상태이고, 앱이 시작하면서 이미 전경을 가져간 상태였다(질문 4 참고). 따라서 "배경에 붙은 창이 클릭을 직접 받는다"는 **검증되지 않았다**. 배경 모드에서는 강아지에 DOM 클릭 리스너를 달지 않았다.
  - ⚠️ 훅 시점의 전경 창은 **클릭 직전** 상태다. 작업 표시줄을 클릭해도 `WorkerW`로 찍혔다. 따라서 "바탕화면 위 클릭"을 전경 창만으로 판정하면 틀린다. `WindowFromPoint` 같은 보완이 필요하다.
  - 확인 못 함: 드래그 선택 방해 여부, 배율 125%/150%(사용자 세션 설정 변경이 필요해 보류), 체감 지연.

### 3. 말풍선 가림 판정

- 사용한 API: `EnumWindows`, `IsWindowVisible`, `IsIconic`, `DwmGetWindowAttribute(DWMWA_CLOAKED, DWMWA_EXTENDED_FRAME_BOUNDS)`. `Progman`, `WorkerW`는 제외.
- 확인 결과
  - ✅ 덮는 창이 없으면 `covered=[]`.
  - ✅ 메모장으로 덮으면 `covered=["Notepad"]`, 치우면 다시 `[]`.
  - ✅ 말풍선이 작업 표시줄 영역에 있으면 `covered=["Shell_TrayWnd"]`.
  - ✅ 바탕화면이 드러난 상태에서 잘못 덮는 것으로 나오는 창은 없었다.
  - ⚠️ **배경 모드에서만 맞다.** 판정이 z-순서를 보지 않고 보이는 최상위 창 전부와 겹치는지만 본다. 배경 모드 창은 항상 맨 아래라 결과가 맞지만, 오버레이 모드 실행 중에는 강아지가 메모장 **위**에 떠 있는데도 `covered=["Notepad"]`가 찍혔다.

### 4. 바탕화면 노출·마지막 입력

- 사용한 API: `GetForegroundWindow` 클래스 비교(`Progman`/`WorkerW`), `GetLastInputInfo` + `GetTickCount`
- 확인 결과
  - ✅ 모든 창 최소화 시 `fg=WorkerW` → 노출. 메모장을 활성화하면 `fg=Notepad`.
  - 확인 못 함: 실제 Win+D 키("바탕화면 보기")로 최소화했을 때. 스크립트(`Shell.Application.MinimizeAll`)로만 최소화했다. 그 상태에서 배경 모드 강아지가 계속 보이는 것은 확인했다.
  - ✅ 입력이 없으면 경과 시간이 늘고, 마우스를 움직이면 547ms로 초기화된다.
  - ⚠️ 앱이 켜지면 우리 창이 전경을 가져간다. 본 구현은 포커스를 가져가지 않고 시작해야 한다.

### 대조: 오버레이 모드

- 사용한 API: Tauri `set_always_on_top`, `set_ignore_cursor_events`, Win32 `GetCursorPos`를 50ms마다 폴링해 커서가 강아지 위에 있을 때만 클릭을 받는다.
- 확인 결과
  - ✅ 강아지가 메모장 위에 뜬다. 투명 영역으로 뒤가 비친다.
  - ✅ 강아지 밖 클릭은 아래 창(메모장)으로 통과한다. 커서가 강아지 위에 오면 클릭을 받는다.
  - CPU: 앱 프로세스가 10초간 0.16초(1코어 기준 약 1.6%). 웹뷰 프로세스는 다른 앱과 섞여 따로 측정하지 못했다.

## 본 구현에 주는 결론

1. **배경 모드 설계 변경 → [0009](../decisions/0009-background-mode-wallpaper-replacement.md)로 결정**: 시도한 방법으로는 배경 모드의 캐릭터 층을 투명하게 할 수 없었다. 앱이 현재 배경화면 그림을 직접 그리는 "배경화면 대체" 방식으로 바꿔야 한다. 이에 따라 다음을 처리해야 한다.
   - 배경화면이 바뀌면(Windows 추천 사진은 매일 바뀜) 다시 읽어 그리기
   - 배경화면 맞춤 방식(채우기·맞춤·늘이기·바둑판) 재현
   - 화질 저하 원인 확인
2. **종료·복구 처리**: 정상 종료 시 창을 떼고 바탕화면을 다시 그리게 한다. 탐색기가 재시작되면 부모 WorkerW와 함께 자식 창도 파괴되므로 **창을 다시 만들어** 붙여야 한다. `TaskbarCreated` 브로드캐스트는 최상위 창만 받으므로, 이를 받을 숨은 최상위 창을 따로 둔다. 비정상 종료로 바탕화면이 검게 남는 경우의 복구 방법도 마련한다.
3. **클릭 판정 보완**: 배경 모드 클릭은 훅 좌표 + 강아지 영역 판정으로 된다. "바탕화면 위 클릭"인지는 전경 창 대신 `WindowFromPoint` 등으로 판정한다. 붙은 창이 클릭을 직접 받는지는 미검증이므로 몸체 단계에서 먼저 확인한다(받는다면 훅이 필요 없을 수 있다).
   - 오버레이 모드에서 가림 판정을 쓰려면 z-순서를 봐야 한다(우리 창보다 위에 있는 창만 대상).
4. **포커스**: 앱 시작과 캐릭터 층은 포커스를 가져가지 않게 한다.
5. **배율**: 125%/150% 배율 확인은 몸체 단계에서 사용자와 함께 한다.
6. 오버레이 모드는 스펙 설계(커서 위치에 따라 클릭 통과 전환)대로 가능하다.
