# 제품 비전

사용자가 컨셉을 공개하는 만큼 누적한다. **확정**은 사용자가 직접 말한 것, **가정**은 아직 확인받지 않은 해석이다.

## 핵심 컨셉 (확정, 2026-10-14)

- PC나 모바일 **배경화면 위에** 움직이는 캐릭터(예: 강아지)가 있다.
- 사용자는 **타이핑으로** 캐릭터에게 말을 건다.
- 캐릭터도 **먼저 말을 건다**.
- **Jev**가 실시간 반응을 결정한다.
  - 사용자가 타이핑을 끝내기 전에도 입력에 반응한다. 여러 감정·액션 중 하나를 Jev가 실시간으로 고른다.
  - 사용자의 말을 **끊고 끼어들 수 있다**.
  - 캐릭터가 먼저 말을 거는 **시점**도 Jev가 고른다.

## 플랫폼 (확정, 2026-10-14)

- **Windows PC를 먼저** 만든다. → [0002](decisions/0002-platform-order.md)
- Android는 그다음이다. Windows가 완성됐다고 사용자가 판단하면 그때 별도로 지시한다. 그 전에는 Android를 설계·구현하지 않는다.

## Windows 표시 모드 (확정, 2026-10-14)

- 두 가지 모드를 모두 지원한다. → [0003](decisions/0003-windows-display-modes.md)
  - **배경 모드**: 바탕화면 아이콘 뒤 레이어. 다른 창에 가려진다.
  - **오버레이 모드**: 항상 위에 떠 있는 투명 창. 작업 창들 위에 보인다.
- 모드는 **사용자 설정으로 고정**한다. 캐릭터가 말을 걸거나 사용자가 불러도 모드가 자동으로 바뀌지 않는다.

## 가정 (확인 필요)

- 끼어들기와 먼저 말 걸기는 같은 메커니즘이다. Jev가 매 순간 "지금 말할까"를 판정한다.
- 반응은 미리 정의한 감정·액션 목록에서 고른다.
- 대사 자체는 Jev가 아닌 별도 LLM이 생성한다. Jev는 텍스트를 생성하지 않기 때문이다 ([참고](references/typesafe-jev.md)).

## 미정

- 배경 모드에서 창에 가려져 있을 때 캐릭터의 선발화·끼어들기를 사용자에게 어떻게 알리는가
- 사용자가 말을 거는 입력창을 여는 방법
- 캐릭터 종류, 성격, 성장·상태 시스템 여부 (프로젝트명의 Tamagotchi와 관련)
- 대상 사용자와 성공 기준
