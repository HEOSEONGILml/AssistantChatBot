# Windows 데스크톱 펫 첫 버전 설계

- 날짜: 2026-10-14
- 상태: 승인됨. 2026-10-14 개정: 배경 모드 제외, 강아지 집 추가 ([0010](../../decisions/0010-overlay-only-with-doghouse.md)). 2026-10-15 개정: 두뇌를 독립 파이썬 서비스로 ([0012](../../decisions/0012-brain-as-frontend-independent-service.md))
- 근거 문서: [vision](../../vision.md), 결정 기록 [0001](../../decisions/0001-jev-as-decision-engine.md)~[0010](../../decisions/0010-overlay-only-with-doghouse.md)

## 1. 목표

Windows 화면 위(항상 위에 떠 있는 투명 창)에 사는 강아지와 타이핑으로 대화한다. 강아지는 타이핑 도중 감정·행동으로 반응하고, 끼어들고, 먼저 말을 걸고, 답하지 않거나 연달아 말하기도 한다. 이 모든 "지금 말할까" 판단을 Jev가 한다.

대상은 개발자 본인과 팀 내부다. 성공 기준은 [vision의 첫 버전 성공 기준](../../vision.md)을 따른다.

### 범위 밖

배경 모드(바탕화면 아이콘 뒤), Android, macOS, 다중 모니터(첫 버전은 주 모니터만), 장기 기억, 성격 변화, 돌봄 상태, 여러 캐릭터, 대화 기록 화면, 외부 배포.

## 2. 서브 프로젝트 분할

첫 버전은 네 단계로 나눈다. 각 단계는 자기 스펙(필요하면)·계획·구현을 거친다.

| 순서 | 서브 프로젝트 | 내용 | 완료 기준 |
|---|---|---|---|
| 0 | 스파이크: 배경 모드 (완료) | 아이콘 뒤 레이어 붙이기, 클릭 감지, 가림 판정이 이 PC에서 되는지 확인 | [결과](../../spikes/background-mode.md). 이후 배경 모드는 제외됨(0010) |
| 1 | 몸체 | Tauri 뼈대, 오버레이 창, 애니메이션, 강아지 집, 입력창, 말풍선, 설정, 트레이 | AI 없이 강아지가 돌아다니고 입력창·말풍선이 동작 |
| 2 | 두뇌 | 스케줄러, Jev 판단, Gemini 대사, 대화 기록, 자리 비움·"봤다" 판정 연동 | 끼어들기·선발화·무응답·연달아 말하기가 일어남 |
| 3 | 평가 | 평가 대화 데이터, 임계값 산출, 지연·비용 측정 | 성공 기준의 품질 항목을 숫자로 확인 |

몸체와 두뇌는 `Signal`/`Reaction` 경계로 분리되어 따로 만들고 테스트할 수 있다.

## 3. 전체 구조

> 2026-10-15 개정: 두뇌는 Tauri 밖의 독립 파이썬 서비스다 ([0011](../../decisions/0011-python-brain-local-sidecar.md), [0012](../../decisions/0012-brain-as-frontend-independent-service.md)). 두뇌 상세는 [두뇌 스펙](2026-10-15-brain-design.md)이 기준이다.

```
┌──────────────── Tauri 앱 (Windows 화면) ─────────────────┐
│  Rust 셸 (src-tauri)                                     │
│   ├ 창 관리: 오버레이(투명, 항상 위, 클릭 통과 전환)      │
│   ├ 입력 감지: 전역 단축키, 트레이 메뉴                   │
│   ├ 시스템 신호: 마지막 입력 시각, 커서 위치, 창 위치      │
│   └ 두뇌 실행: 두뇌가 없으면 띄운다                       │
│            │ 이벤트 ↑↓ 명령                               │
│  TypeScript 프론트엔드                                    │
│   └ 몸체 (body/): 애니메이션, 돌아다니기, 강아지 집,       │
│                   말풍선, 입력창, 설정 화면               │
└───────────────┬──────────────────────────────────────────┘
                │ WebSocket (localhost): Signal ↓  ↑ Reaction
┌───────────────┴──── 두뇌 서비스 (brain/, 파이썬) ─────────┐
│   ├ 스케줄러: 언제 Jev를 부를지                            │
│   ├ 판단기: Jev 호출 → 감정·행동·말할지                   │
│   ├ 화자: Gemini 호출 → 대사                             │
│   ├ 기억: 대화 기록 저장, 최근 N개 조회                     │
│   └ 키 보관: OS 자격 저장소                               │
└──────────────────────────────────────────────────────────┘
```

### 3.1 몸체와 두뇌의 경계

- 몸체 → 두뇌 `Signal`: 타이핑 중인 글 변경, 메시지 보냄, 강아지 집에 들어감/나옴, 몸 상호작용(찌르기·쓰다듬기·던지기), 이벤트(사용자 자리 비움/복귀, 말풍선을 봤음).
- 두뇌 → 몸체 `Reaction`: 감정, 행동, 대사(없을 수 있음).
- 두뇌는 화면을 모른다. 두뇌는 고정이고 화면은 바뀔 수 있다(예: 나중에 Android). 프로토콜은 `docs/brain-protocol.md`가 기준이다.

### 3.2 창 구성

- **캐릭터 층**: 주 모니터의 작업 영역(작업 표시줄 제외)을 덮는 투명 창 하나. 창에 문제가 생겨도 작업 표시줄과 트레이 메뉴는 쓸 수 있어야 하므로 작업 표시줄은 덮지 않는다 (2026-10-14: 개발 서버가 꺼져 오류 페이지가 화면 전체를 덮은 사고 후 변경). 항상 위. 강아지, 강아지 집, 말풍선을 이 안에 그린다. 강아지가 움직여도 창은 움직이지 않는다.
  - 커서가 집·말풍선 아이콘 위에 있을 때만 클릭을 받고, 그 외에는 클릭을 아래 창으로 통과시킨다. 커서 위치는 Rust에서 폴링한다(스파이크에서 50ms 주기로 확인).
  - 캐릭터 층과 앱 시작은 포커스를 가져가지 않는다.
- **입력창**: 별도의 작은 창. 항상 위. 강아지 위치와 상관없이 강아지 집 위에 뜬다. 포커스를 받아야 타이핑할 수 있으므로 캐릭터 층과 분리한다.
- **설정 창**: 트레이 아이콘 메뉴로 연다.

### 3.3 저장

- 화면 설정: Tauri 앱 데이터 폴더의 로컬 파일.
- 대화 기록: 두뇌 데이터 폴더의 SQLite ([두뇌 스펙](2026-10-15-brain-design.md) 6절).
- API 키(TypeSafe, Gemini): 두뇌가 OS 자격 저장소(Windows 자격 증명 관리자)에 보관한다. 평문 파일에 쓰지 않는다 (2026-10-15 개정, [0012](../../decisions/0012-brain-as-frontend-independent-service.md)).
- 대화 기록은 무기한 보관하고 설정에서 전체 삭제할 수 있다. 화면에는 보여주지 않는다.

### 3.4 외부 호출

- Jev와 Gemini(`gemini-3.1-flash-lite`)는 두뇌(파이썬)가 호출한다. 화면은 외부 AI를 직접 부르지 않는다 (2026-10-15 개정). 상세는 [두뇌 스펙](2026-10-15-brain-design.md).

## 4. 두뇌

> 2026-10-15: 이 절은 처음 합의한 뼈대다. 확정 내용(감정·행동 목록, 잠정값, 상호작용 트리거 등)은 [두뇌 스펙](2026-10-15-brain-design.md)이 기준이다.

### 4.1 Jev 질문 (요청 1회에 세 질문)

| 이름 | 타입 | 내용 |
|---|---|---|
| `emotion` | choice | 강아지의 지금 감정 |
| `action` | choice | 강아지의 지금 행동 |
| `speak_now` | noul | "강아지가 지금 말을 하는 게 자연스럽다" |

- 감정 후보 예: 신남, 궁금함, 반가움, 시무룩, 놀람, 졸림, 평온. 행동 후보 예: 꼬리 흔들기, 갸웃, 뛰어다니기, 앉기, 엎드리기, 짖기, 어슬렁거리기. 행동마다 애니메이션이 하나 필요하므로 최종 목록은 몸체 계획에서 확정한다.
- 끼어들기, 선발화, 답할지, 한 마디 더 할지를 모두 `speak_now` 하나로 묻는다. 상황은 `state`로만 구분한다.
- 질문 정의는 한 파일에서 관리한다 (CLAUDE.md 4절).

### 4.2 state 구성

강아지 성격 설명, 현재 시각, 상황(타이핑 중 / 방금 보냄 / 조용함 / 강아지가 방금 말함), 타이핑 중인 글, 최근 대화 N개, 마지막 대화 이후 경과 시간, 안 읽힌 말풍선 여부.
자리 비움 여부는 넣지 않는다. 호출 주기에만 쓴다. 집에서 막 나왔다면 집에 있던 시간을 넣는다.

### 4.3 스케줄러

| 상황 | 호출 시점 |
|---|---|
| 타이핑 중 | 새로 입력된 글자가 K자 이상, 또는 타이핑이 멈춘 뒤 T초. 새 호출 시 진행 중 요청은 취소 |
| 사용자가 보냄 | 즉시 |
| 강아지가 방금 말함 | 즉시 (연달아 말할지 판단) |
| 조용함 | 사용자가 자리에 있으면 주기 P_active, 자리 비움(마지막 입력 후 오래 지남)이면 P_away |
| 이벤트 (사용자 복귀, 강아지가 집에서 나옴) | 즉시. 집에서 나올 때는 집에 있던 시간을 state에 넣는다 |
| 강아지가 집에 있음 | 호출하지 않는다 |

### 4.4 판단 이후 흐름

1. Jev 응답의 감정·행동을 즉시 `Reaction`으로 보낸다. 대사를 기다리지 않는다.
2. `speak_now`가 임계값 이상이면 Gemini로 대사를 만든다. 입력: 성격, 감정, 행동, 최근 대화, 상황.
3. 대사 생성 중 상황이 바뀌면(예: 끼어들 말을 만드는 사이 사용자가 메시지를 보냄) 그 대사는 버린다.
4. 사용자 입력 없이 강아지가 연속으로 말할 수 있는 횟수에 상한을 둔다. 무한 발화와 비용 폭주를 막는다.

### 4.5 서브 프로젝트 2에서 잠정값을 정하고 3에서 확정할 값

K(글자 수), T(멈춤 시간), P_active, P_away, 자리 비움 판정 시간, `speak_now` 임계값, 최근 대화 개수 N, 연속 발화 상한, 말풍선 "봤다" 노출 시간, 판정 후 유지 시간.
잠정값은 근거(또는 "잠정값")와 함께 두뇌 계획과 코드 상수 주석에 기록한다.

## 5. 몸체

- **애니메이션**: 행동별 스프라이트 시트. 감정은 행동×감정 조합마다 그림을 따로 그려 표현한다(2026-10-15 사용자 요청으로 개정, 두뇌 다음 몸체 작업에서 설계). 첫 그림은 Claude가 임시로 만든다. 첫 버전은 무료 스프라이트나 임시 그림을 쓰고 파일 교체로 바꿀 수 있게 한다.
- **그림**: 픽셀아트. 강아지는 [Benvictus Pixel Dogs](https://benvictus.itch.io/pixel-dogs)(64×48). 동작 이름과 시트 위치는 manifest 파일로 관리해 그림을 쉽게 교체한다. 강아지 집은 간단한 픽셀아트로 직접 만든다.
- **이동**: 화면(작업 영역) 어디로든 2차원으로 움직인다. 바닥선에만 묶이지 않는다 (2026-10-14 사용자 요청, mochi 참고). 창 위에 올라앉기는 다음 단계에서 다룬다.
- **평소 움직임(자율 행동)**: Jev가 고른 행동이 없을 때 규칙으로 정한다. 쉬지 않고 왕복하지 않는다. [mochi-llm-pet](../../references/similar-projects.md)의 방식을 참고했다 (2026-10-14 사용자 요청).
  - 대부분은 **가만히 있는다**: 서기·앉기·엎드리기 중 하나를 무작위로 골라 몇 초씩 유지한다.
  - 가끔 **가까운 곳까지 걸어가 멈춘다**. 목표 방향(2차원)과 거리는 무작위이고, 가끔은 달린다.
  - 커서가 가까우면 **커서 쪽을 바라보고**, 가끔 커서 쪽으로 다가가 조금 앞에서 멈춘다.
  - 사용자가 오래 입력하지 않으면 엎드렸다가 **잠든다**. 사용자가 돌아오면 깬다.
  - 확률·시간·거리 값은 잠정값으로 코드 상수에 둔다.
- **강아지 집**: 화면 구석(작업 표시줄 위 오른쪽)에 있다. 집을 클릭하거나 트레이 메뉴·단축키로 강아지를 넣고 꺼낸다. 넣으면 강아지가 어디에 있든 집으로 빠르게 뛰어 들어가고 말풍선이 사라진다. 집에 있는 동안은 완전히 조용하다(Jev 호출 없음). 들어가 있을 때 집도 숨길지는 설정으로 정한다.
- **말풍선**: 강아지 머리 위를 따라다닌다. 최신 하나만 보인다. 사용자가 PC를 쓰는 동안(마지막 입력 후 1분 이내, 잠정값) 노출된 시간만 세어 일정 시간이 되면 "봤다"로 판정해 `Signal`을 보내고, 몇 초 뒤(최소 5초, 글자당 0.15초, 잠정값) 사라진다. 오버레이라 가림 판정은 하지 않는다 (2026-10-14 개정, vision).
- **크기**: 강아지는 스프라이트 1.5배 (2026-10-14 사용자 요청으로 축소).
- **움직임 정도** (vision): 평소 움직임의 가중치·대기 시간·달리기 확률을 단계별 프로필로 바꾼다. 쉬기는 이동하는 행동을 모두 빼고 그 자리에서 잔다(사용자가 자리에 있어도 깨지 않음). 상호작용으로 잠깐 반응한 뒤에는 다시 잔다. 성격과 무관한 고정값이며, 성격 연동은 이후 "성격 따름" 단계로 추가한다.
- **먼저 하는 인터랙션** (vision): 평소 움직임 규칙이 가끔 고른다(확률은 잠정값).
  - 근처 클릭: 커서 폴링 때 마우스 왼쪽 버튼 상태(`GetAsyncKeyState`)를 함께 읽어 눌림을 감지한다(다른 창의 클릭도 감지, 강아지·아이콘 클릭은 제외). 최근 3초 안에 강아지 근처(450px)에서 클릭이 있으면 다가가기·따라가기·사냥 가중치를 4배로 하고, 대기 중이면 절반 확률로 바로 다음 행동을 고른다(잠정값).
  - 커서 따라가기: 정해진 시간 동안 커서에서 조금 떨어진 곳을 목표로 지연 추종(스프링)한다. 멀면 달린다.
  - 커서 사냥: 커서로 달려가다 가까워지면 짧은 포물선 점프로 커서 위치를 덮친다. 점프는 그림을 위로 띄우는 높이 오프셋으로 표현한다.
  - 창 위에 올라앉기: 대상 창 윗변의 한 지점으로 가서 앉는다. 매 프레임 창 위치를 다시 읽어 따라간다. 창이 사라지거나 최소화되면 그 자리에서 떨어진다(던지기와 같은 낙하).
  - 주변 관찰: 대상 창 옆 바닥 쪽으로 가서 창 가운데를 바라보며 앉아 있는다. 창이 사라지면 그만둔다.
  - 창 정보: Rust 명령이 보이는(최소화·숨김이 아닌) 최상위 창의 위치·크기와 활성 여부만 돌려준다. 우리 앱의 창과 너무 작은 창은 뺀다. 창 제목은 읽지 않는다.
- **몸 상호작용** (vision): 찌르기(짧은 클릭 → 짖기), 쓰다듬기(강아지 위에서 커서를 좌우로 여러 번 문지름 → 조르기), 잡아 던지기(누른 채 6px 넘게 끌면 잡힘 → 놓는 순간 커서 속도가 초당 600px 미만이면 그 자리에 내려놓고, 이상이면 그 속도로 날아가 중력으로 떨어지며 화면 끝에서 튕기고 바닥에 세게 닿으면 한 번 더 튕긴 뒤 작업 영역 바닥에 착지). 커서가 강아지 몸 위에 있으면 고개 돌리기·따라가기·사냥을 하지 않아 쓰다듬기와 겹치지 않고, 평소 움직임 중이면 무엇을 하든 쓰다듬기를 받는다(2026-10-15 사용자 보고로 수정). Jev를 거치지 않는 즉시 반응이며 `Signal { kind: "interaction" }`으로 두뇌에 알린다. 판정 값은 잠정값.
- 강아지가 집에 들어가면 입력창을 닫고, 집에 있는 동안은 입력창을 열지 않는다.
- **말풍선 모양**: mochi-llm-pet을 참고한다. 둥근 상자(반지름 9px), 얇은 테두리, 살짝 비치는 흰 배경, 13px 글자 가운데 정렬, 강아지 머리 위 가운데에 놓고 아래 꼬리로 강아지를 가리킨다 (2026-10-14 사용자 요청).
- **입력창**: 강아지 집 위에 뜬다. 집 옆 말풍선 아이콘(누를 때마다 열기/닫기) 또는 전역 단축키(기본 `Ctrl+Shift+Space`, 설정에서 변경 가능)로 연다. Enter로 보낸다. 상시 표시 설정이 꺼져 있으면 보낸 뒤 닫힌다. 입력 내용 변경을 두뇌로 계속 보낸다.
- **설정**: 톱니바퀴 아이콘(말풍선 아이콘 옆) 또는 트레이 메뉴로 연다. 항목: 움직임 정도(쉬기·차분·보통·활발), 입력창 상시 표시, 강아지가 집에 있을 때 집 숨기기, 단축키, TypeSafe 키, Gemini 키, 대화 기록 전체 삭제.
- **첫 실행**: 키가 없으면 돌아다니기만 하고 "설정에서 키를 넣어 주세요" 말풍선을 띄운다.

구현: 서브 프로젝트 1 완료(`app/`). 수동 확인 결과는 [docs/manual-checks/body.md](../../manual-checks/body.md).

## 6. 오류 처리

원칙: 강아지는 멈추지 않는다.

| 상황 | 동작 |
|---|---|
| Jev 실패·시간 초과 | 이번 판단 건너뜀. 다음 트리거에 재시도. 로그 기록 |
| Gemini 실패 | 대사 없이 감정·행동만 표시 |
| 키 오류 (401/403) | 반복 호출하지 않음. "키를 확인해 주세요" 말풍선. 설정에서 키를 다시 저장할 때까지 AI 호출 중단 |
| 네트워크 끊김 | 연속 실패 시 호출 간격을 점점 늘림(백오프) |
| 대화 기록 읽기·쓰기 실패 | 메모리 내용으로 계속. 로그 기록 |

로그는 앱 데이터 폴더 파일에 남긴다. 키와 대화 내용은 로그에 쓰지 않는다.

## 7. 테스트

- **두뇌 (Vitest)**: 가짜 Jev·Gemini·시계로 다음을 검증한다.
  - 스케줄러: K자 입력, 멈춤 후 T초, 이벤트가 각각 호출을 일으킴. 새 호출이 이전 요청을 취소함.
  - 판단 흐름: 임계값 미만이면 대사 없음(무응답). 연속 발화 상한. 상황 변경 시 대사 폐기.
  - 오류 처리: 6절 표의 각 동작.
- **Rust 셸**: Win32 신호(커서, 마지막 입력)는 얇은 래퍼라 수동 확인한다. Win32 의존 부분은 스파이크와 수동 체크리스트로 검증한다.
- **몸체**: 핵심 흐름(입력창 열기, 말풍선 표시, 강아지 집 넣고 꺼내기)을 수동 체크리스트로 확인한다.
- **평가 (서브 프로젝트 3)**: 평가 대화 데이터로 임계값·지연·비용을 측정한다. 방식은 용인FC `tests/eval`을 참고한다.

## 8. 서브 프로젝트 0: 배경 모드 스파이크

이 PC는 Windows 10 Pro 19045다.

**확인할 질문**

1. Tauri 투명 창을 바탕화면 아이콘 뒤 레이어(WorkerW)에 붙일 수 있는가? 붙인 뒤에도 투명 배경과 애니메이션이 정상으로 그려지는가?
2. 배경 모드에서 전역 저수준 마우스 훅으로 클릭 좌표를 받아, 바탕화면이 보이는 상태에서 강아지 영역 클릭을 판정할 수 있는가? 바탕화면 아이콘 클릭 같은 기존 동작을 방해하지 않는가?
3. 캐릭터 층의 특정 영역(말풍선)이 다른 창에 가려졌는지 판정할 수 있는가?
4. 바탕화면이 노출되었는지(모든 창 최소화 등)와 사용자 마지막 입력 시각을 얻을 수 있는가?

**방법**: 최소 Tauri 앱에 Rust `windows` 크레이트로 각 질문을 시험한다. 쓰기 전에 Context7로 Tauri와 `windows` 크레이트 문서를 확인한다.

**산출물**: `docs/spikes/background-mode.md`에 질문별 결과(된다/안 된다/조건부), 사용한 API, 주의점을 기록한다. 스파이크 코드는 버린다. 본 구현에서 다시 쓴다.

**실패 시**: 1이 안 되면 배경 모드를 다른 방식으로 바꾸는 결정을 사용자와 다시 한다. 2가 안 되면 배경 모드의 클릭 대신 단축키만 쓰는 방안을 사용자와 다시 정한다.

**결과**: [docs/spikes/background-mode.md](../../spikes/background-mode.md) — 질문 1은 조건부(투명 불가) → 배경화면 대체 방식으로 결정([0009](../../decisions/0009-background-mode-wallpaper-replacement.md)). 3.2절과 6절에 반영했다.
