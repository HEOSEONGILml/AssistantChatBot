# Windows 데스크톱 펫 첫 버전 설계

- 날짜: 2026-10-14
- 상태: 승인됨. 2026-10-14 개정: 배경 모드 제외, 강아지 집 추가 ([0010](../../decisions/0010-overlay-only-with-doghouse.md))
- 근거 문서: [vision](../../vision.md), 결정 기록 [0001](../../decisions/0001-jev-as-decision-engine.md)~[0010](../../decisions/0010-overlay-only-with-doghouse.md)

## 1. 목표

Windows 화면 위(항상 위에 떠 있는 투명 창)에 사는 강아지와 타이핑으로 대화한다. 강아지는 타이핑 도중 감정·행동으로 반응하고, 끼어들고, 먼저 말을 걸고, 답하지 않거나 연달아 말하기도 한다. 이 모든 "지금 말할까" 판단을 Jev가 한다.

대상은 개발자 본인과 팀 내부다. 성공 기준은 [vision의 첫 버전 성공 기준](../../vision.md)을 따른다.

### 범위 밖

배경 모드(바탕화면 아이콘 뒤), Android, macOS, 다중 모니터(첫 버전은 주 모니터만), 장기 기억, 성격 변화, 돌봄 상태, 여러 캐릭터, 대화 기록 화면, 외부 배포.

## 2. 서브 프로젝트 분할

첫 버전은 네 단계로 나눈다. 각 단계는 자기 스펙(필요하면)·계획·구현을 거친다.

| 순서 | 서브 프로젝트 | 내용 | 완료 기준 |
|---|---|---|---|
| 0 | 스파이크: 배경 모드 (완료) | 아이콘 뒤 레이어 붙이기, 클릭 감지, 가림 판정이 이 PC에서 되는지 확인 | [결과](../../spikes/background-mode.md). 이후 배경 모드는 제외됨(0010) |
| 1 | 몸체 | Tauri 뼈대, 오버레이 창, 애니메이션, 강아지 집, 입력창, 말풍선, 설정, 트레이 | AI 없이 강아지가 돌아다니고 입력창·말풍선이 동작 |
| 2 | 두뇌 | 스케줄러, Jev 판단, Gemini 대사, 대화 기록, 가시성·"봤다" 판정 연동 | 끼어들기·선발화·무응답·연달아 말하기가 일어남 |
| 3 | 평가 | 평가 대화 데이터, 임계값 산출, 지연·비용 측정 | 성공 기준의 품질 항목을 숫자로 확인 |

몸체와 두뇌는 `Signal`/`Reaction` 경계로 분리되어 따로 만들고 테스트할 수 있다.

## 3. 전체 구조

```
┌──────────────────────── Tauri 앱 ────────────────────────┐
│  Rust 셸 (src-tauri)                                     │
│   ├ 창 관리: 오버레이(투명, 항상 위, 클릭 통과 전환)      │
│   ├ 입력 감지: 전역 단축키, 트레이 메뉴                   │
│   ├ 시스템 신호: 말풍선 가림, 마지막 입력 시각, 커서 위치  │
│   └ 키 보관: Windows 자격 증명 보호                       │
│            │ 이벤트 ↑↓ 명령                               │
│  TypeScript 프론트엔드                                    │
│   ├ 몸체 (body/): 애니메이션, 돌아다니기, 강아지 집,       │
│   │               말풍선, 입력창, 설정 화면               │
│   │      │ Signal ↓        ↑ Reaction                    │
│   └ 두뇌 (brain/): 화면을 모르는 순수 로직                 │
│       ├ 스케줄러: 언제 Jev를 부를지                        │
│       ├ 판단기: Jev 호출 → 감정·행동·말할지               │
│       ├ 화자: Gemini 호출 → 대사                         │
│       └ 기억: 대화 기록 저장, 최근 N개 조회                 │
└──────────────────────────────────────────────────────────┘
```

### 3.1 몸체와 두뇌의 경계

- 몸체 → 두뇌 `Signal`: 타이핑 중인 글 변경, 메시지 보냄, 강아지 집에 들어감/나옴, 이벤트(사용자 자리 비움/복귀, 말풍선을 봤음).
- 두뇌 → 몸체 `Reaction`: 감정, 행동, 대사(없을 수 있음).
- 두뇌는 화면과 Tauri를 모른다. Jev·Gemini 클라이언트, 저장소, 시계는 생성 시 주입한다. 테스트에서는 가짜를 넣는다.

### 3.2 창 구성

- **캐릭터 층**: 주 모니터 전체를 덮는 투명 창 하나. 항상 위. 강아지, 강아지 집, 말풍선을 이 안에 그린다. 강아지가 움직여도 창은 움직이지 않는다.
  - 커서가 강아지·집 영역 위에 있을 때만 클릭을 받고, 그 외에는 클릭을 아래 창으로 통과시킨다. 커서 위치는 Rust에서 폴링한다(스파이크에서 50ms 주기로 확인).
  - 캐릭터 층과 앱 시작은 포커스를 가져가지 않는다.
- **입력창**: 별도의 작은 창. 항상 위. 강아지 근처에 뜬다. 포커스를 받아야 타이핑할 수 있으므로 캐릭터 층과 분리한다.
- **설정 창**: 트레이 아이콘 메뉴로 연다.

### 3.3 저장

- 대화 기록과 설정: 앱 데이터 폴더의 로컬 파일. 형식(SQLite 또는 JSON)은 두뇌 계획에서 정한다.
- API 키(TypeSafe, Gemini): Windows 자격 증명 보호로 따로 보관한다. 평문 파일에 쓰지 않는다.
- 대화 기록은 무기한 보관하고 설정에서 전체 삭제할 수 있다. 화면에는 보여주지 않는다.

### 3.4 외부 호출

- Jev: `TypeSafeClient`에 `fetch`로 Tauri HTTP 플러그인의 fetch를, `dangerouslyAllowBrowser: true`를 넘긴다 ([레퍼런스](../../references/typesafe-jev.md)).
- Gemini: `gemini-3.1-flash-lite`. 호출은 Tauri HTTP 플러그인을 거친다. SDK 사용법은 두뇌 계획 작성 전에 Context7로 확인한다.
- HTTP 플러그인 scope에는 TypeSafe와 Gemini API 주소만 허용한다.

## 4. 두뇌

### 4.1 Jev 질문 (요청 1회에 세 질문)

| 이름 | 타입 | 내용 |
|---|---|---|
| `emotion` | choice | 강아지의 지금 감정 |
| `action` | choice | 강아지의 지금 행동 |
| `speak_now` | noul | "강아지가 지금 말을 하는 게 자연스럽다" |

- 감정 후보 예: 신남, 궁금함, 반가움, 시무룩, 놀람, 졸림, 평온. 행동 후보 예: 꼬리 흔들기, 갸웃, 뛰어다니기, 앉기, 엎드리기, 짖기, 어슬렁거리기. 행동마다 애니메이션이 하나 필요하므로 최종 목록은 몸체 계획에서 확정한다.
- 끼어들기, 선발화, 답할지, 한 마디 더 할지를 모두 `speak_now` 하나로 묻는다. 상황은 `state`로만 구분한다.
- 질문 정의는 한 파일에서 관리한다 (CLAUDE.md 4절).

### 4.2 state 구성

강아지 성격 설명, 현재 시각, 상황(타이핑 중 / 방금 보냄 / 조용함 / 강아지가 방금 말함), 타이핑 중인 글, 최근 대화 N개, 마지막 대화 이후 경과 시간, 안 읽힌 말풍선 여부.
자리 비움 여부는 넣지 않는다. 호출 주기에만 쓴다. 집에서 막 나왔다면 집에 있던 시간을 넣는다.

### 4.3 스케줄러

| 상황 | 호출 시점 |
|---|---|
| 타이핑 중 | 새로 입력된 글자가 K자 이상, 또는 타이핑이 멈춘 뒤 T초. 새 호출 시 진행 중 요청은 취소 |
| 사용자가 보냄 | 즉시 |
| 강아지가 방금 말함 | 즉시 (연달아 말할지 판단) |
| 조용함 | 사용자가 자리에 있으면 주기 P_active, 자리 비움(마지막 입력 후 오래 지남)이면 P_away |
| 이벤트 (사용자 복귀, 강아지가 집에서 나옴) | 즉시. 집에서 나올 때는 집에 있던 시간을 state에 넣는다 |
| 강아지가 집에 있음 | 호출하지 않는다 |

### 4.4 판단 이후 흐름

1. Jev 응답의 감정·행동을 즉시 `Reaction`으로 보낸다. 대사를 기다리지 않는다.
2. `speak_now`가 임계값 이상이면 Gemini로 대사를 만든다. 입력: 성격, 감정, 행동, 최근 대화, 상황.
3. 대사 생성 중 상황이 바뀌면(예: 끼어들 말을 만드는 사이 사용자가 메시지를 보냄) 그 대사는 버린다.
4. 사용자 입력 없이 강아지가 연속으로 말할 수 있는 횟수에 상한을 둔다. 무한 발화와 비용 폭주를 막는다.

### 4.5 서브 프로젝트 2에서 잠정값을 정하고 3에서 확정할 값

K(글자 수), T(멈춤 시간), P_active, P_away, 자리 비움 판정 시간, `speak_now` 임계값, 최근 대화 개수 N, 연속 발화 상한, 말풍선 "봤다" 노출 시간, 판정 후 유지 시간.
잠정값은 근거(또는 "잠정값")와 함께 두뇌 계획과 코드 상수 주석에 기록한다.

## 5. 몸체

- **애니메이션**: 행동별 스프라이트 시트. 감정은 표정·머리 위 아이콘 오버레이로 표현해 행동×감정 조합을 모두 그리지 않는다. 첫 버전은 무료 스프라이트나 임시 그림을 쓰고 파일 교체로 바꿀 수 있게 한다.
- **그림**: 픽셀아트. 강아지는 [Benvictus Pixel Dogs](https://benvictus.itch.io/pixel-dogs)(64×48). 동작 이름과 시트 위치는 manifest 파일로 관리해 그림을 쉽게 교체한다. 강아지 집은 간단한 픽셀아트로 직접 만든다.
- **이동**: 화면 아래 바닥선(작업 표시줄 위)을 따라 걷는다. Jev가 고른 행동이 없을 때 기본 행동은 어슬렁거리기다.
- **강아지 집**: 화면 구석(작업 표시줄 위 오른쪽)에 있다. 집을 클릭하거나 트레이 메뉴·단축키로 강아지를 넣고 꺼낸다. 넣으면 강아지가 걸어 들어가고 말풍선이 사라진다. 집에 있는 동안은 완전히 조용하다(Jev 호출 없음). 들어가 있을 때 집도 숨길지는 설정으로 정한다.
- **말풍선**: 강아지 머리 위를 따라다닌다. 최신 하나만 보인다. 다른 창에 가려지지 않고 일정 시간 노출되면 "봤다"로 판정해 `Signal`을 보내고, 그 뒤 오래 유지했다가 사라진다. 가림 판정은 Rust 셸이 하며, 캐릭터 층보다 **z-순서가 위인 창만** 본다(전체 화면 앱, 다른 항상 위 창 등). 스파이크에서 z-순서를 보지 않으면 오판하는 것을 확인했다.
- **입력창**: 캐릭터 클릭 또는 전역 단축키(기본 `Ctrl+Shift+Space`, 설정에서 변경 가능)로 연다. Enter로 보낸다. 상시 표시 설정이 꺼져 있으면 보낸 뒤 닫힌다. 입력 내용 변경을 두뇌로 계속 보낸다.
- **설정**: 입력창 상시 표시, 강아지가 집에 있을 때 집 숨기기, 단축키, TypeSafe 키, Gemini 키, 대화 기록 전체 삭제.
- **첫 실행**: 키가 없으면 돌아다니기만 하고 "설정에서 키를 넣어 주세요" 말풍선을 띄운다.

구현: 서브 프로젝트 1 완료(`app/`). 수동 확인 결과는 [docs/manual-checks/body.md](../../manual-checks/body.md).

## 6. 오류 처리

원칙: 강아지는 멈추지 않는다.

| 상황 | 동작 |
|---|---|
| Jev 실패·시간 초과 | 이번 판단 건너뜀. 다음 트리거에 재시도. 로그 기록 |
| Gemini 실패 | 대사 없이 감정·행동만 표시 |
| 키 오류 (401/403) | 반복 호출하지 않음. "키를 확인해 주세요" 말풍선. 설정에서 키를 다시 저장할 때까지 AI 호출 중단 |
| 네트워크 끊김 | 연속 실패 시 호출 간격을 점점 늘림(백오프) |
| 대화 기록 읽기·쓰기 실패 | 메모리 내용으로 계속. 로그 기록 |

로그는 앱 데이터 폴더 파일에 남긴다. 키와 대화 내용은 로그에 쓰지 않는다.

## 7. 테스트

- **두뇌 (Vitest)**: 가짜 Jev·Gemini·시계로 다음을 검증한다.
  - 스케줄러: K자 입력, 멈춤 후 T초, 이벤트가 각각 호출을 일으킴. 새 호출이 이전 요청을 취소함.
  - 판단 흐름: 임계값 미만이면 대사 없음(무응답). 연속 발화 상한. 상황 변경 시 대사 폐기.
  - 오류 처리: 6절 표의 각 동작.
- **Rust 셸 (cargo test)**: 순수 로직만 (예: 사각형 교차, z-순서상 위 창들로 가림 판정). Win32 의존 부분은 스파이크와 수동 체크리스트로 검증한다.
- **몸체**: 핵심 흐름(입력창 열기, 말풍선 표시, 강아지 집 넣고 꺼내기)을 수동 체크리스트로 확인한다.
- **평가 (서브 프로젝트 3)**: 평가 대화 데이터로 임계값·지연·비용을 측정한다. 방식은 용인FC `tests/eval`을 참고한다.

## 8. 서브 프로젝트 0: 배경 모드 스파이크

이 PC는 Windows 10 Pro 19045다.

**확인할 질문**

1. Tauri 투명 창을 바탕화면 아이콘 뒤 레이어(WorkerW)에 붙일 수 있는가? 붙인 뒤에도 투명 배경과 애니메이션이 정상으로 그려지는가?
2. 배경 모드에서 전역 저수준 마우스 훅으로 클릭 좌표를 받아, 바탕화면이 보이는 상태에서 강아지 영역 클릭을 판정할 수 있는가? 바탕화면 아이콘 클릭 같은 기존 동작을 방해하지 않는가?
3. 캐릭터 층의 특정 영역(말풍선)이 다른 창에 가려졌는지 판정할 수 있는가?
4. 바탕화면이 노출되었는지(모든 창 최소화 등)와 사용자 마지막 입력 시각을 얻을 수 있는가?

**방법**: 최소 Tauri 앱에 Rust `windows` 크레이트로 각 질문을 시험한다. 쓰기 전에 Context7로 Tauri와 `windows` 크레이트 문서를 확인한다.

**산출물**: `docs/spikes/background-mode.md`에 질문별 결과(된다/안 된다/조건부), 사용한 API, 주의점을 기록한다. 스파이크 코드는 버린다. 본 구현에서 다시 쓴다.

**실패 시**: 1이 안 되면 배경 모드를 다른 방식으로 바꾸는 결정을 사용자와 다시 한다. 2가 안 되면 배경 모드의 클릭 대신 단축키만 쓰는 방안을 사용자와 다시 정한다.
