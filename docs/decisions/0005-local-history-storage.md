# 0005. 대화 기록은 PC에만 저장하고, Jev·LLM 호출은 서버가 중계한다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

대화 기록을 어디에 둘지에 따라 서버가 필요한지, API 키를 어디에 둘지가 달라진다.

## 결정

- 대화 기록은 사용자 PC에만 저장한다.
- Jev와 LLM 호출은 **중계 서버**를 거친다. 서버는 API 키를 숨기고 요청을 전달하는 역할만 한다. 대화 기록은 서버에 저장하지 않는다.

사용자가 지정한 사항이다. 처음에는 "PC에만 저장, 앱이 직접 호출"로 정했다가 같은 날 이 방식으로 바꿨다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| PC에만 저장, 앱이 직접 호출 | 서버가 필요 없다. 지연이 가장 적다 | API 키가 앱 안에 놓인다 | 키 노출을 피하려고 중계를 택했다 |
| 서버에 저장 | 기기 간 동기화가 가능하다 | 대화 기록 저장소를 운영해야 한다 | 사용자가 로컬 저장을 선택했다 |

## 결과

- 대화 내용은 서버에 저장되지 않는다. 다만 Jev·LLM 요청에 담겨 서버를 통과한다. **서버는 요청 본문을 로그에 남기지 않는다.**
- 서버를 거치는 만큼 지연이 늘어난다. 타이핑 중 실시간 반응은 Jev 왕복 지연에 민감하므로, 설계 단계에서 중계 경로의 지연을 측정한다.
- 중계 서버를 어디에 둘지(Bigglz-AI-core에 붙일지, 별도로 둘지) 정해야 한다.
- 앱이 서버에 접속할 때의 인증 방식을 정해야 한다. 인증이 없으면 누구나 중계 서버로 Jev·LLM을 호출할 수 있다.
- Android로 확장할 때 기기 간 대화 이어가기는 지원하지 않는다. 필요해지면 그때 다시 검토한다.
