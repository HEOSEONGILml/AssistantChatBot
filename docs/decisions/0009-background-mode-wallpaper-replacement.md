# 0009. 배경 모드는 "배경화면 대체" 방식으로 구현한다

- 상태: 채택
- 날짜: 2026-10-14
- 근거: [배경 모드 스파이크 결과](../spikes/background-mode.md)
- 수정: [0003](0003-windows-display-modes.md)의 배경 모드 구현 방식

## 배경

스파이크에서 캐릭터 창을 바탕화면 아이콘 뒤 레이어(WorkerW)에 붙이는 데는 성공했다. 하지만 붙인 창의 투명 영역이 검게 칠해져 배경화면을 가렸다. 자식 창에서는 웹뷰의 알파 투명이 합성되지 않는다. 색상 키 방식으로 두 번 시도했지만 모두 실패했다. (`UpdateLayeredWindow`, DirectComposition 직접 제어는 시도하지 않았다.)
반면 앱이 현재 배경화면 그림을 직접 읽어 창 배경으로 그리자 정상으로 보였다.

## 결정

배경 모드에서는 **앱이 배경화면 자체가 된다.** 캐릭터 층은 투명 창이 아니라, 현재 배경화면 그림을 그리고 그 위에 강아지와 말풍선을 그리는 불투명 창이다. 이 창을 아이콘 뒤 레이어에 붙인다.

사용자가 판단을 맡겨 Claude가 정했다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 배경 모드를 빼고 오버레이만 | 구현이 단순하다 | 사용자가 정한 "두 모드 모두 지원"(0003)을 어긴다 | 사용자 요구를 지킬 방법이 있다 |
| 투명을 계속 시도 (DirectComposition 직접 다루기 등) | 배경화면을 복제하지 않아도 된다 | 두 번 실패했고, 될지 알 수 없다. 웹뷰 내부 합성을 건드려야 한다 | 성공 가능성이 낮고 비용이 크다 |
| 배경화면 대체 (채택) | 스파이크로 동작을 확인했다. 배경화면 앱들이 쓰는 검증된 방식이다 | 배경화면 변경·맞춤 방식·화질을 직접 처리해야 한다 | — |

## 결과

배경 모드 구현에 다음이 필요하다. 모두 몸체(서브 프로젝트 1) 범위다.

1. **배경화면 읽기**: `SystemParametersInfoW(SPI_GETDESKWALLPAPER)`로 파일 경로를 얻어 그린다.
2. **배경화면 변경 감지**: 설정 변경 알림(`WM_SETTINGCHANGE` + `SPI_SETDESKWALLPAPER`)을 받으면 다시 읽는다. Windows 추천 사진(Spotlight)은 알림 없이 파일만 바뀔 수 있으므로 파일 수정 시각도 주기적으로 확인한다.
3. **단색 배경·슬라이드쇼**: 배경화면 파일이 없으면(단색) 배경색을 칠한다. 슬라이드쇼는 현재 표시 중인 파일을 따라간다.
4. **맞춤 방식 재현**: 레지스트리 `WallpaperStyle`·`TileWallpaper` 값에 따라 채우기·맞춤·늘이기·가운데·바둑판을 CSS로 재현한다. 단색 배경이면 배경색을 칠한다.
5. **화질**: 스파이크에서 색이 뭉개져 보였다. 원본 파일과 렌더링 결과를 비교해 원인을 찾고 해결한다. 해결되지 않으면 사용자에게 보고한다.
6. **종료 처리**: 정상 종료 시 창을 떼고 바탕화면을 다시 그리게 한다. 비정상 종료로 바탕화면이 검게 남으면 탐색기 재시작으로 복구된다(스파이크에서 확인). 다음 실행 때 앱이 스스로 복구하는 처리는 몸체에서 구현하고 확인한다. 복구 방법을 설정 화면 도움말에 적는다.
7. **탐색기 재시작**: 부모 WorkerW와 함께 캐릭터 창도 파괴되므로 창을 **다시 만들어** 붙인다. 재시작 신호(`TaskbarCreated`)는 최상위 창만 받으므로 이를 받을 숨은 최상위 창을 둔다.
8. **실패 시**: 붙이기나 배경화면 읽기가 실패하면 오버레이 모드로 대신 띄운다 (스펙 6절과 같다).

다중 모니터에서는 모니터마다 배경화면이 다를 수 있다. 첫 버전은 주 모니터만 다루므로 이 문제는 다중 모니터를 지원할 때 다시 본다.
