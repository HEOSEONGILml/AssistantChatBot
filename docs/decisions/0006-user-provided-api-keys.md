# 0006. 중계 서버 없이 사용자가 직접 입력한 API 키로 Jev·LLM을 호출한다

- 상태: 채택
- 날짜: 2026-10-14
- 대체: [0005](0005-local-history-storage.md)의 "서버 중계" 부분

## 배경

0005에서는 API 키를 숨기려고 Jev·LLM 호출을 중계 서버로 보내기로 했다.
하지만 중계 서버를 두면 서버 운영, 앱 인증, 추가 지연 문제가 생긴다.

## 결정

- 별도 서버를 두지 않는다. 앱의 모든 코드는 사용자 PC에서 동작한다.
- 사용자가 자기 Jev·LLM API 키를 **설정 화면에 직접 입력**한다. 앱은 이 키로 Jev와 LLM을 직접 호출한다.
- 대화 기록은 0005대로 PC에만 저장한다.

사용자가 지정한 사항이다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 중계 서버 (0005) | 사용자가 키를 몰라도 된다 | 서버 운영, 앱 인증, 추가 지연 | 서버를 두지 않기로 했다 |
| 앱에 키 내장 | 사용자가 설정할 게 없다 | 배포하면 키가 노출된다 | 키 노출 |

## 결과

- **코드는 모두 로컬에서 돌지만, 데이터가 전부 로컬에 머무는 것은 아니다.** Jev와 LLM은 외부 클라우드 API다. 판단과 대사 생성을 할 때 타이핑 중인 텍스트와 최근 대화가 TypeSafe와 LLM 업체로 전송된다.
- 사용자마다 TypeSafe 키가 필요하다. Jev는 얼리 액세스라 키 발급이 대기자 명단을 거친다. 일반 사용자가 쓰기에는 진입 장벽이 된다.
- 키를 평문 파일로 저장하지 않는다. Windows 자격 증명 보호(예: DPAPI, 자격 증명 관리자)를 쓴다. 구체적인 방법은 설계에서 정한다.
- 키가 없거나 잘못된 경우 앱이 어떻게 동작할지(첫 실행 안내, 오류 표시)를 설계에서 정한다.
- 비용은 사용자 각자의 키로 청구된다.
