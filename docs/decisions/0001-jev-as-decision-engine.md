# 0001. 실시간 반응 결정에 Jev를 쓴다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

캐릭터는 사용자가 타이핑하는 도중에도 반응하고, 끼어들고, 먼저 말을 걸어야 한다.
이런 판단은 키 입력마다, 혹은 일정 간격으로 계속 내려야 하므로 빠르고 싸야 한다.
범용 LLM으로 매번 판단하면 응답이 수 초 걸리고 비용도 커서 실시간 반응이 어렵다.

## 결정

반응 결정(감정, 액션, 끼어들기 여부, 선발화 여부)은 TypeSafe **Jev**가 맡는다.
사용자가 서비스 기본 컨셉으로 지정한 사항이다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 범용 LLM이 매번 판단 | 유연하다. 대사와 판단을 한 번에 낼 수 있다 | 느리고 비싸다. 출력 형식이 흔들릴 수 있다 | 실시간 반응에 맞지 않다 |
| 규칙 기반 (키워드, 타이머) | 즉각적이고 무료다 | 맥락을 이해하지 못한다 | 캐릭터가 기계적으로 보인다 |

## 결과

- Jev는 텍스트를 만들지 않는다. 캐릭터 대사는 별도 생성 수단이 필요하다 (별도 결정 예정).
- 판단 질문(choice/noul)과 임계값을 설계하고, 평가 데이터로 임계값을 정해야 한다.
- 업체가 밝힌 지연 시간은 70~500ms다. 독립 검증된 값이 아니므로 실제 측정 후 호출 주기를 정한다.
- Jev는 얼리 액세스 단계다. API 키 확보와 가용성을 확인해야 한다. 사내 `TYPESAFE_API_KEY_*` 사용 사례가 있다.
