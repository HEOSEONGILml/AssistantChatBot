# 0007. 캐릭터 대사는 gemini-3.1-flash-lite로 생성한다

- 상태: 채택
- 날짜: 2026-10-14

## 배경

Jev는 텍스트를 만들지 않는다([0001](0001-jev-as-decision-engine.md)). 캐릭터의 대사는 별도 LLM이 만들어야 한다.
대사 생성은 다음 성격을 가진다.

- 지연이 체감된다. 끼어들기는 사용자가 타이핑을 멈춘 순간에 나와야 자연스럽다.
- 호출이 잦다. 성격이 수다스럽고, 연달아 말하기(1발화 N답변)도 허용한다.
- 어려운 추론이 필요 없다. 성격이 드러나는 짧은 한두 문장이면 된다.

## 결정

대사 생성 LLM으로 Google **`gemini-3.1-flash-lite`**를 쓴다. 사용자가 지정한 사항이다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| Claude Haiku / Sonnet / Opus 5.5 | 모델 선택 폭이 넓다 | 사내 사용 경험이 적다 | 사용자가 Gemini를 선택했다 |
| 설정에서 업체·모델 선택 | 사용자 자유도가 높다 | 업체마다 연동 코드가 필요하다 | 첫 버전은 업체 하나로 단순하게 간다 |

## 결과

- 사용자가 설정에 넣는 키는 **TypeSafe(Jev) 키와 Gemini 키** 두 개다([0006](0006-user-provided-api-keys.md)).
- 사내에서 이미 쓰는 모델이다. 용인FC 챗봇의 재작성·답변 생성 등 여러 프롬프트가 이 모델을 쓴다 (`Bigglz-AI-core/src/prompt_hub/yongin/*.yaml`).
- 구현 전에 Context7 등으로 Gemini SDK의 최신 사용법을 확인한다.
- 대사 생성 지연은 반응 속도 기준(입력 후 1초 이내)과 함께 측정한다. 끼어들기 대사가 늦으면 모델 변경을 다시 검토한다.
