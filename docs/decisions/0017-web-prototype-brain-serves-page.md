# 0017. 웹 프로토타입은 두뇌가 페이지와 WebSocket을 함께 낸다

- 상태: 채택 (프로토타입)
- 날짜: 2026-10-19

## 배경

사용자가 "프론트를 웹 페이지로 배포하는 버전"을 요청했다. 프로토타입이고 기술 판단은 위임받았다. 브라우저는 파이썬 두뇌를 띄울 수 없고, PC 앱처럼 `brain.json`에서 포트·토큰을 읽을 수도 없다. 그래서 브라우저가 두뇌를 어떻게 찾고 인증하는지 정해야 했다.

## 결정

두뇌에 웹 모드(`python -m brain.web`)를 더한다. 한 포트에서 정적 웹 화면, `/token`, `/ws`(프로토콜 v3)를 낸다. 브라우저는 페이지와 같은 출처로 토큰을 받아 접속하고, 두뇌는 `/ws`의 Origin이 Host와 같을 때만 받는다. 웹 두뇌는 PC 두뇌와 다른 데이터 폴더를 쓴다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 정적 사이트(GitHub Pages 등) + 사용자 PC의 두뇌에 `ws://localhost`로 접속 | 페이지만 배포하면 된다 | 사용자가 두뇌를 따로 설치·실행해야 하고, 토큰을 페이지에 넘길 방법이 없다(파일을 못 읽음) | 웹 버전의 뜻(브라우저만으로)과 멀다 |
| 별도 웹 서버(nginx 등) + 두뇌 WebSocket | 정석적인 배포 | 프로세스·설정이 둘. 프로토타입에 과하다 | 단순성 |
| 두뇌를 브라우저에서 돌림(Pyodide 등) | 서버가 필요 없다 | 키가 브라우저에 노출되고, SQLite·keyring·SDK 이식이 크다 | 비용이 너무 크다 |
| **두뇌가 페이지와 WebSocket을 함께 냄 (채택)** | 명령 하나로 뜬다. 같은 출처라 토큰·CORS가 단순하다 | 두뇌가 정적 파일까지 낸다 | 프로토타입에 가장 단순하다 |

## 결과

- 두뇌에 웹 진입점(`brain/brain/web.py`)이 생긴다. 판단 코드(`core.py`)는 바뀌지 않는다.
- `config.py`가 키를 환경 변수에서도 읽는다(자격 저장소가 없는 서버).
- 다른 기기에 열면 키가 서버에 있어 주소를 아는 누구나 쓴다. 정식 웹 버전에서는 사용자 구분·인증을 다시 정한다.
