# 0013. 두뇌는 이벤트 단위로 판단하고, 이벤트 기록을 기억으로 쓴다

- 상태: 채택
- 날짜: 2026-10-15
- 대체: [두뇌 스펙 v1](../superpowers/specs/2026-10-15-brain-design.md)의 스케줄러(4.3절)와 대화 기록(6절)

## 배경

첫 두뇌(v1)는 두뇌 안의 스케줄러가 Jev 호출 시점을 정했다(K자 입력, T초 멈춤, 조용함 주기, "방금 말함" 예약). 기억은 대화 기록만 있었다.
실제로 써 보니 끼어들지 않고 늘 3번 말하는 문제가 나왔다([실측](../spikes/2026-10-15-jev-speak-now-probe.md)). 사용자와 판단 구조를 처음부터 다시 논의했다.

## 결정

- **Jev 호출은 이벤트 단위다.** 두뇌는 이벤트가 올 때마다 항상 같은 처리를 한다. **이벤트를 언제 낼지는 화면이 판단한다.** 두뇌에는 타이머·스케줄러가 없다.
- 이벤트의 **의미**는 프로토콜에 고정하고 **시점**만 화면마다 다르다.
- 이벤트: 타이핑, 메시지 보냄, 강아지 말이 화면에 뜸, 조용함, 돌아옴, 집에 들어감, 집에서 나옴, 찌르기, 쓰다듬기, 던지기. 이벤트에 그 순간의 맥락(쓰던 글, 충격 등)을 싣는다.
- **대화도 이벤트다.** 두뇌는 대화 기록 대신 **이벤트 기록**을 저장한다. 강아지 자신의 반응·동작·말도 같은 기록에 들어간다.
- 판단 중에 온 이벤트는 모아 두었다가 끝나면 한 번에 판단한다.

이벤트 단위·화면이 시점 판단·이벤트 기록·이벤트 목록은 사용자가 정했다. 기록을 두뇌에 두는 것, 맥락 싣기, 모아서 판단하기는 Claude가 제안하고 사용자가 수용했다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 두뇌 안 스케줄러 (v1) | 화면이 단순하다 | 입력 방식(키보드/터치)마다 다른 "타이핑 멈춤"을 두뇌가 알 수 없다. 두뇌가 복잡해진다 | 이벤트를 가장 잘 아는 화면이 정한다 |
| 이벤트 기록을 화면이 저장해 매번 전달 | 두뇌가 순수 함수가 된다 | 화면마다 저장을 만들어야 하고 기록이 화면별로 갈린다 | 두뇌는 고정, 화면은 바뀜 ([0012](0012-brain-as-frontend-independent-service.md)) |
| 판단 중 이벤트: 줄 세우기 / 최신 우선 | 단순하다 | 밀리거나(지난 일에 늦게 반응) 빠진다(기분 변화 손실) | 모아서 판단하면 둘 다 없다 |

## 결과

- 두뇌가 단순해진다. 평가는 "이벤트 순서" 데이터를 두뇌에 넣어 한다.
- 화면(Windows)이 타이핑 멈춤·조용함 타이머·말풍선 표시 이벤트를 새로 낸다.
- 프로토콜이 v2로 바뀐다(`docs/brain-protocol.md`).
- 설계: [두뇌 스펙 v2](../superpowers/specs/2026-10-15-brain-v2-design.md)
