# 0021. 웹은 접속마다 강아지가 새로 태어나고 저장하지 않는다

- 상태: 채택 (프로토타입)
- 날짜: 2026-10-20
- 대체: [0017](0017-web-prototype-brain-serves-page.md)의 "두뇌 하나 = 강아지 하나 = 접속한 탭 하나" 부분

## 배경

웹 두뇌는 강아지 한 마리와 연결 하나만 두었다. 탭이 둘이면 서로 연결을 빼앗아 대답이 다른 탭으로 갔다(2026-10-20, 로그에 하루 4천여 번 재접속). 사용자는 여러 탭·여러 사람이 동시에 쓰고, 사람마다 자기 강아지를 갖기를 원했다.

## 결정

웹 모드는 WebSocket 접속 하나마다 `Brain` 하나를 새로 만든다. 저장소는 메모리만 쓴다(`Store(None)`). 접속이 끊기면 그 강아지는 사라진다. 키는 서버 시작 때 한 번 읽고 모든 강아지가 같이 쓴다. 웹에서는 `set_key`를 받지 않는다. PC 모드는 그대로다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| 같은 강아지를 모든 탭에 방송 | 강아지가 하나로 이어진다 | 탭마다 내는 조용함·대사 되돌림·집 상태가 겹친다 | 사용자가 사람마다 다른 강아지를 골랐다 |
| 브라우저 ID(또는 로그인)마다 강아지를 저장 | 새로고침해도 강아지가 이어진다 | ID 발급, 강아지별 저장소, 같은 사람의 여러 탭 처리가 필요하다 | 사용자 제안: 접속마다 새로 태어나면 훨씬 단순하다 |
| **접속마다 새 강아지, 메모리만 (채택)** | `web.py`만 바꾸면 된다. 탭끼리 부딪힐 일이 없다 | 새로고침·잠깐 끊김에도 새 강아지다. 탭 수만큼 Jev·Gemini 호출이 는다 | 프로토타입에 가장 단순하다 |

## 결과

- `brain/brain/web.py`가 접속마다 `Link`·`Brain`·기분 시계를 만들고 끊기면 정리한다. `core.py`는 바뀌지 않는다.
- 웹 데이터 폴더에는 로그만 남는다. 예전 `brain.db`는 쓰지 않는다.
- 웹 화면에서 키 입력란과 4002 처리를 뺀다(웹에서는 연결을 빼앗기는 일이 없다).
