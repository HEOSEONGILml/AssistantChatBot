# 0011. 두뇌는 PC 안에서 도는 파이썬 프로세스로 만든다

- 상태: 채택
- 날짜: 2026-10-14
- 수정: [0008](0008-tech-stack-tauri.md)의 "TypeScript 프론트엔드가 판단·대사 로직을 맡는다" 부분

## 배경

처음 설계(0008, 스펙 3절)에서는 두뇌(스케줄러, Jev 판단, Gemini 대사, 대화 기록)를 TypeScript 프론트엔드 안에 두었다.
사용자가 두뇌를 파이썬으로 만드는 방안을 제안했다.

## 결정

- 두뇌는 **파이썬 프로세스**로 만들고 **사용자 PC 안에서만** 돌린다. Tauri 앱이 함께 띄우고, 앱을 끌 때 함께 정리한다.
- 몸체(Tauri)와 두뇌(파이썬)는 PC 안에서만 열리는 연결(localhost)로 `Signal`·`Reaction`을 주고받는다.
- 서버를 두지 않는다는 결정([0006](0006-user-provided-api-keys.md))과 대화 기록을 PC에만 둔다는 결정([0005](0005-local-history-storage.md))은 그대로다.
- Android는 지금 고려하지 않는다 ([0002](0002-platform-order.md)).

사용자가 제안하고 정한 사항이다.

## 검토한 대안

| 대안 | 장점 | 단점 | 채택하지 않은 이유 |
|---|---|---|---|
| TypeScript 두뇌 (프론트엔드 안) | 프로세스 하나. 배포가 단순하다. Jev TS SDK의 타입 추론 | 평가(서브 프로젝트 3)를 파이썬으로 하면 두뇌 로직을 따로 흉내 내야 한다. 사내 파이썬 자산을 못 쓴다 | 평가와 두뇌가 같은 코드를 쓰는 이점이 크다 |
| 파이썬 두뇌를 원격 서버에 | 다른 기기와 공유하기 쉽다 | 0005·0006을 다시 정해야 한다. 서버 지연이 실시간 반응에 더해진다 | 키·대화 기록을 PC에 둔다는 원칙을 지킨다 |

## 결과

- 평가 스크립트가 두뇌 코드를 그대로 불러 쓴다. 임계값 산출과 실제 동작이 어긋나지 않는다.
- 용인FC(`Bigglz-AI-core`)의 Jev 연동·프롬프트 관리·재시도 패턴을 참고할 수 있다. Jev(`typesafe-sdk`)와 Gemini 모두 파이썬 SDK가 있다.
- API 키는 지금처럼 Windows 자격 증명에 둔다. 파이썬 두뇌가 키를 읽는 방법(같은 `keyring`으로 직접 읽기 등)은 두뇌 설계에서 정한다.
- 개발 PC에는 파이썬이 필요하다. 배포용 묶음(실행 환경 포함)은 외부 배포를 할 때 정한다(현재 범위 밖).
- 두뇌 프로세스가 죽거나 늦게 뜨는 경우의 몸체 동작(임시 두뇌로 대체 등)을 두뇌 설계에서 정한다.
