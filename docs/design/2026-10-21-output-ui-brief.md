# 디자인 요청: 출력 계층 사용자 인터페이스

Claude Design에 주는 작업 지시서다. 결과물은 이 저장소로 다시 가져와 출력 계층 설계에 쓴다.

## 1. 제품 소개

Windows PC에서 도는 **computer-use 에이전트**다.

- 사용자의 **화면 히스토리**를 백그라운드에서 기록해 둔다. 그래서 사용자가 작업 맥락을 일일이 설명하지 않아도 하고자 하는 일을 알아듣는다.
  - 예: "아까 슬랙에서 본 링크, 카톡 이 사람한테 보내 줘"
- 사용자가 요청하면 대답하거나, 브라우저 같은 프로그램을 **직접 조작해서** 일을 처리한다.
- 정해 둔 시간에 스스로 도는 **스케줄 작업**도 있다.
- 화면 한 자리에 **강아지** 모습으로 있다. 돌아다니지 않는다.

비슷한 제품과의 차이는 이렇다.
- Microsoft UFO², Claude Cowork는 실행은 잘하지만 사용자가 맥락을 직접 주고 작업을 일일이 지시해야 한다.
- screenpipe는 화면 히스토리를 기억하지만 일은 하지 않는다.
- 이 제품은 둘을 잇는다. 전문 도구만큼 무겁지 않고, 사용자 곁에서 짧은 말로 일을 맡기는 조수다.

## 2. 디자인할 범위

**출력 계층**, 즉 에이전트가 사용자에게 보여 주는 사용자 인터페이스다. 사용자가 그 화면에서 바로 하는 반응(질문에 답하기, 멈추기)도 포함한다.

범위 밖:
- 컴퓨터를 조작하는 일 자체. 백엔드가 하고 화면에 나타나지 않는다.
- 화면 기록. 백그라운드에서 돈다.

## 3. 보여 줄 것 (입출력 인터페이스)

프론트와 백엔드는 아래 메시지로 이어진다. 디자인은 각 메시지가 왔을 때 사용자가 무엇을 보는지, 사용자가 무엇을 해서 어떤 메시지가 나가는지를 정한다.

### 백엔드 → 프론트: 보여 줄 것

| 메시지 | 담는 것 | 뜻 |
|---|---|---|
| `task_started` | 작업 ID, 출처(사용자·스케줄), 요청 글 | 작업이 시작됨 |
| `progress` | 작업 ID, 한 줄 글 | 진행 상황. 예: "쿠팡에서 검색 중" |
| `question` | 작업 ID, 질문 ID, 질문 글, 고를 수 있는 답(있을 때만) | 사용자 확인이 필요함. 예: "결제할까요?" |
| `result` | 작업 ID, 대답 글 | 끝남 |
| `failed` | 작업 ID, 이유 | 못 함 |
| `stopped` | 작업 ID | 사용자 요청대로 멈춤 |
| `status` | `ok` 또는 `no_keys` | AI 키 상태. `no_keys`면 설정에서 키를 넣으라고 안내해야 한다 |

### 프론트 → 백엔드: 사용자가 하는 것

| 메시지 | 담는 것 | 사용자 행동 |
|---|---|---|
| `request` | 요청 글 | 요청하기 |
| `reply` | 작업 ID, 질문 ID, 답 글 | 질문에 답하기 |
| `stop` | 작업 ID | 작업 멈추기 |

## 4. 지금 있는 것

- **입력창**: 전역 단축키(기본 `Ctrl+Shift+Space`)로 화면 가운데에 뜨는 한 줄 입력창. Enter로 보내고 Esc로 닫는다. 디자인에 맞춰 바꿔도 된다.
- **트레이 아이콘**: 설정 창 열기, 종료.
- **설정 창**: 입력창 단축키, API 키.
- **강아지 그림**: 픽셀아트 스프라이트(`app/public/sprites/dog/dog-02.png`, 64×48 프레임). 서기·앉기·엎드리기·잠·조르기·짖기·걷기·달리기 동작이 있다. 출처: [Benvictus – Pixel Dogs](https://benvictus.itch.io/pixel-dogs).

## 5. 기술 조건

- Windows 10/11 데스크톱 앱. 화면은 Tauri(웹뷰)라 HTML·CSS·TypeScript로 만든다.
- 사용자는 다른 프로그램(브라우저, 슬랙, 카카오톡 등)으로 일하는 중이다. 이 앱은 그 옆에 함께 있다.

## 6. 아직 정하지 않은 것

디자인 제안을 보고 정한다. 안을 여러 개 내도 좋다.

- 화면 어디에 강아지가 있는지
- 진행·질문·결과를 어떤 모양으로 보여 주는지 (예: 말풍선, 패널, 알림)
- 작업 중에 덧붙여 지시하는 것을 넣을지
- 동시에 도는 작업이 하나인지 여럿인지. 스케줄 작업이 사용자 작업과 겹칠 수 있다
- 사용자가 자리에 없을 때 끝난 스케줄 작업의 결과를 어떻게 보여 주는지

## 7. 받고 싶은 결과물

- 위 메시지별 화면 상태(작업 없음, 진행 중, 질문, 결과, 실패, 멈춤, 키 없음)
- 사용자 작업과 스케줄 작업이 어떻게 구분되어 보이는지
- 질문에 답하기와 멈추기의 조작 방법
- 강아지의 위치와 상태 표현
